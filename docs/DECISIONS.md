# Decisions

Принятые правила; это не дневник запусков и не список завершённых задач.
Операционные записи и evidence находятся в приватном `.local/`.

| ID | Решение и граница |
| --- | --- |
| D-01 | Первоначально была разрешена только локальная основа `engineering-practice`. Новое живое разрешение отдельно покрывает проверенную основу, workflow и EP-001 в существующем `randoomiggy/labs` с текущими Git name/email. Remote и commit/push разрешены для этого набора, но не для будущих автоматических публикаций, установки инструментов, смены visibility или global Git config. |
| D-02 | Цели — личное обучение и достоверное портфолио для поиска работы. Не создавать фиктивный опыт, показатели или активность ради streak. |
| D-03 | Объяснения и сотрудничество — по-русски; code identifiers и корневой README — по-английски. Полное решение даётся сразу, attempt-first необязателен. |
| D-04 | Первые 14 задач — оригинальные, offline, Python stdlib + unittest. Только синтетические fixtures; никаких employer logs, PII и credentials. |
| D-05 | Требуемое ежедневное время — 09:30 local `America/Vancouver`, с учётом timezone, не фиксированный UTC offset. Конфигурация и доставка проверяются вне репозитория. |
| D-06 | Автоматика готовит только private pending snapshots и реальные проверки. Cron не меняет tracked tree/Git и никогда не вызывает `decide`. Молчание оставляет вопрос нерешённым. |
| D-07 | ID/версия/fingerprint связывают конкретный immutable payload и base. Изменения требуют новой версии и нового согласия; старое согласие не переносится. |
| D-08 | Только live agent после точного сообщения пользователя в Telegram записывает решение. CLI проверяет условия, но не аутентифицирует отправителя. `approve` не применяет и не публикует файлы. |
| D-09 | Account attribution, repo access, visibility, назначение и точный diff проверяются отдельно перед живой публикацией. Глобальный Git author не доказывает владение аккаунтом. Scaffold требует собственной проверки; не включать его молча в первый task commit. |
| D-10 | `AGENTS.md` — политика, `ROADMAP.md` — план, `BACKLOG.json` — очередь предложений, `.local/` — приватные записи. Reviewed/proposed не означает learned. После seed-набора новая задача предлагается без автоматического редактирования curriculum. |
| D-11 | Существенные постоянные изменения workflow требуют явного локального согласия. Изменения tracked docs/instructions/backlog показываются отдельными proposed diffs и отдельно одобряются перед commit. |
| D-12 | Новое упражнение запрещено, пока более ранние предложения не обработаны и явно не одобрены для коммита. Pending/revision_requested/rejected не дают перейти дальше; пропущенные дни не создают пачку задач. Уже существующие pending сохраняются. |
| D-13 | Weekly review проверяет фактические mutation calls против живого согласия. Preparation-only cron не меняет skills/память/инструкции; полезные находки только предлагает. |
| D-14 | Telegram-сводка краткая; полная карточка отправляется отдельной обезличенной копией. Исходные snapshots и raw evidence неизменны, `.gitignore` не заменяет проверку содержимого вложения. |

## Пока не выбрано

- Первая публикация требует завершённой проверки точного diff и remote readback;
  разрешение на публикацию само по себе ещё не доказывает выполненный push.
- Лицензия: файл `LICENSE` не создаётся до выбора пользователя.
- Конкретный operational lab, CI/IaC и любые дополнительные зависимости.

Изменять этот документ только в согласованном объёме; историю запусков сюда
не переносить. Возможные будущие решения обозначать как предложения.
